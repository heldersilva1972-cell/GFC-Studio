# GFC Native Mode Migration (Model B: APK-First)

## Overview
The "Model B: APK-First" strategy ensures that the GFC web application reliably identifies itself as a native application when running inside the Android APK. This solves the issue of duplicate notification prompts (browser vs. OS) and provides a better onboarding experience.

## Core Principles
1. **Explicit Declaration**: We no longer rely on complex "detection" of the environment. Instead, we use explicit signals like URL parameters and session cookies.
2. **Early Injection**: The native environment flag (`window.__GFC_NATIVE_APP__`) is initialized at the absolute top of the `<head>` in `_Host.cshtml` to ensure it's available for all subsequent scripts.
3. **Prompt Interception**: When in native mode, the browser's `Notification.requestPermission` API is intercepted and blocked immediately to prevent Chrome from showing its own window.

## Implementation Details

### 1. Environment Detection (`_Host.cshtml`)
The following script block runs as the first child of `<head>`:

```javascript
(function() {
    const urlParams = new URLSearchParams(window.location.search);
    const isExplicitNative = urlParams.has('native') || urlParams.has('apk') || 
                             !!window.Android || document.cookie.includes('gfc_native=true');
    
    if (isExplicitNative) {
        window.__GFC_NATIVE_APP__ = true;
        document.cookie = "gfc_native=true; path=/; SameSite=Lax";
        
        // Block browser notifications to prevent duplicates
        if (window.Notification && window.Notification.requestPermission) {
            window.Notification.requestPermission = function() {
                return Promise.resolve('denied'); 
            };
        }
    }
})();
```

### 2. URL Signaling
All invitation and setup links generated by the system now include `?native=true`.
- **Route**: `/setup/device`
- **Parameters**: `token=XXXX`, `native=true`, `station=true` (optional)

### 3. PWA Manifest
The `manifest.json` has been updated with:
```json
"start_url": "/?native=true"
```
This ensures that even when launched as a standalone PWA, the app persists its native state.

### 4. Setup & Enrollment (`SetupDevice.razor`)
The enrollment flow has been unified:
- Landing on `/setup/device?token=XXXX` validates the invite.
- It generates the appropriate **Device Trust Token** (Mobile or Station).
- It binds the native notification prompt specifically to a button, ensuring the OS-level prompt only appears when the user explicitly clicks "Get Notifications".

## Future-Proofing
If you encounter issues with "Browser Alerts" appearing in the APK again:
1. Check the browser console. You should see `[GFC] Model B: Native Environment Active`.
2. Verify the URL includes `?native=true`.
3. Check that the script block in `_Host.cshtml` hasn't been moved or modified. It **must** run before the Blazor runtime starts.
